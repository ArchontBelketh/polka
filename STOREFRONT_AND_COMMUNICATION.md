## Блок 3 — Сообщения покупатель ↔ разработчик

**Цель:** покупатель, у которого продукт не запустился, пишет разработчику,
а не сразу открывает спор. Один тред = одна покупка.

### Ключевые решения

1. **Тред привязан к Purchase**, не к паре пользователей — контекст (какой продукт,
   какая версия) всегда ясен, и доступ проверяется одним условием.
2. **Писать может только покупатель с PAID/DELIVERED покупкой и автор продукта.**
   До покупки общение идёт через публичный Q&A (Блок 4) — это защищает от увода
   сделок мимо платформы.
3. **Эскалация в спор из переписки:** кнопка «Открыть спор» в треде; при открытии
   спора модератор видит всю переписку — мгновенный контекст для разрешения.
4. **Email и Telegram участников друг другу не раскрываются** — уведомления
   уходят через платформу.

### Prisma

```prisma
model PurchaseMessage {
  id         String   @id @default(cuid())
  purchaseId String
  senderId   String
  text       String   @db.Text
  isRead     Boolean  @default(false)
  createdAt  DateTime @default(now())
  purchase   Purchase @relation(fields: [purchaseId], references: [id], onDelete: Cascade)
  sender     User     @relation(fields: [senderId], references: [id])

  @@index([purchaseId])
  @@index([senderId])
}

// В model Purchase добавить:
//   messages       PurchaseMessage[]
//   lastMessageAt  DateTime?          // для сортировки списка диалогов
// В model User добавить:
//   purchaseMessages PurchaseMessage[]
```

### API

| Метод | URL | Описание | Доступ |
|-------|-----|----------|--------|
| GET  | `/api/purchases/[id]/messages` | Сообщения треда + пометить входящие прочитанными | Buyer / Author |
| POST | `/api/purchases/[id]/messages` | Отправить сообщение (max 2000 символов) | Buyer / Author |
| GET  | `/api/messages/unread` | Счётчик непрочитанных для бейджа в Navbar | Auth |

Проверка доступа в обоих роутах:

```ts
const purchase = await db.purchase.findUnique({
  where: { id },
  include: { product: { select: { authorId: true, title: true } } },
})
const isBuyer  = purchase?.buyerId === session.user.id
const isAuthor = purchase?.product.authorId === session.user.id
if (!purchase || (!isBuyer && !isAuthor)) return 403
if (!["PAID", "DELIVERED", "DISPUTED", "REFUNDED"].includes(purchase.status)) return 403
```

## Блок 4 — Q&A на странице продукта

**Цель:** снять предпокупочные вопросы публично — каждый ответ работает на всех
будущих покупателей. Один вопрос → один ответ автора (без веток, это не форум).

### Ключевые решения

1. **Вопрос виден всем сразу** с пометкой «Ожидает ответа» — это мягкое давление
   на разработчика отвечать быстро.
2. **Отвечает только автор продукта.** Редактировать ответ можно, удалять вопрос — нельзя
   (может модератор).
3. **Фильтр на обмен контактами** — в публичном Q&A до покупки нельзя оставлять
   телефон/email/телеграм: иначе сделки уйдут мимо платформы.

### Prisma

```prisma
model ProductQuestion {
  id         String    @id @default(cuid())
  productId  String
  authorId   String
  question   String    @db.Text
  answer     String?   @db.Text
  answeredAt DateTime?
  isHidden   Boolean   @default(false)   // скрыт модератором
  createdAt  DateTime  @default(now())
  product    Product   @relation(fields: [productId], references: [id], onDelete: Cascade)
  author     User      @relation(fields: [authorId], references: [id])

  @@index([productId])
}
```

### API

| Метод | URL | Описание | Доступ |
|-------|-----|----------|--------|
| GET    | `/api/products/[id]/questions` | Список (не скрытые), новые сверху | Все |
| POST   | `/api/products/[id]/questions` | Задать вопрос (max 1000 символов) | Auth |
| PATCH  | `/api/questions/[id]` | Ответить / отредактировать ответ | Author продукта |
| DELETE | `/api/questions/[id]` | Скрыть (isHidden = true) | Moderator |

### Фильтр контактов (`src/lib/contact-filter.ts`)

```ts
const CONTACT_PATTERNS = [
  /(\+7|8)[\s(-]?\d{3}[\s)-]?\d{3}[\s-]?\d{2}[\s-]?\d{2}/,  // телефон РФ
  /[a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}/i,                  // email
  /(t\.me\/|@[a-z0-9_]{5,})/i,                               // telegram
  /(wa\.me|whatsapp|viber)/i,
]
// При совпадении → 400 «Обмен контактами до покупки запрещён правилами платформы»
```

## Блок 6 — Дубликаты файлов и бейдж «Проверено вручную»

### 6a. SHA-256 и проверка дубликатов

**Цель:** не дать перезалить чужой продукт как свой и заблокировать повторную
отправку отклонённого файла (упомянуто в AUTO_MODERATION.md — довести до кода).

```prisma
model ProductFile {
  // ... существующие поля ...
  sha256 String? @db.VarChar(64)

  @@index([sha256])
}
```

- [ ] Считать hash в сканере (`src/lib/scanner/index.ts`) — файл там уже скачан из S3;
      писать в `ProductFile.sha256`
- [ ] Проверка в оркестраторе перед инструментами:
      - hash совпадает с файлом **другого автора** → `WARNING` «Возможный дубликат
        продукта „X“» + фактор `+30` в risk-score → ручная очередь
      - hash совпадает с файлом продукта со статусом `SCAN_FAILED`/`REJECTED` → `CRITICAL`
        (мгновенный AUTO_REJECT, файл уже отклонялся)
- [ ] Вывод находки в карточке модерации со ссылкой на продукт-оригинал

### 6b. Бейдж «Проверено вручную»

**Цель:** компенсировать то, что модерация не запускает продукты. Модератор, который
реально установил и запустил продукт, ставит отметку — у покупателя появляется
сильный сигнал доверия. На старте проставить всем onboard-продуктам.

```prisma
model Product {
  // ...
  manuallyVerified Boolean   @default(false)
  verifiedAt       DateTime?
}
```

- [ ] Кнопка «Подтвердить работоспособность» в `/admin/review/[id]` (MODERATOR/ADMIN),
      запись в ModerationLog (action: `VERIFIED`)
- [ ] `src/components/product/VerifiedBadge.tsx` — бейдж с тултипом
      «Модератор ПОЛКИ установил и запустил этот продукт»; на ProductCard и странице продукта
- [ ] Сортировка каталога «популярные»: проверенные получают буст в ранжировании
- [ ] При загрузке новой версии бейдж снимается (`manuallyVerified = false`) —
      проверка относится к конкретному файлу

## Что сознательно НЕ делаем сейчас

- **WebSocket/realtime чат** — polling 15 сек достаточно при текущем объёме
- **Треды и ветки в Q&A** — один вопрос, один ответ; уточнения через новый вопрос
- **Сообщения до покупки** — только публичный Q&A, иначе сделки уйдут мимо платформы
- **Вложения в сообщениях** — текст + ссылки на свои покупки; файлы = вектор атак
- **Публичный чат-форум платформы** — несёт расходы на модерацию, ценности мало
