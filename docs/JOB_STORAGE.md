# Приватные файлы заказов

Обмен файлами входит в [пакет D1](PACKAGE_D_ORDERS.md).
Код требует отдельный бакет, указанный в серверной переменной:

```dotenv
YANDEX_S3_PRIVATE_BUCKET="имя-закрытого-бакета"
```

Используются существующие `YANDEX_S3_ACCESS_KEY`, `YANDEX_S3_SECRET_KEY`,
`YANDEX_S3_ENDPOINT` и `YANDEX_S3_REGION`. Это серверные параметры, без
`NEXT_PUBLIC_`. Без бакета/ключей загрузка возвращает 503, записи о файле нет.
Действующие файлы магазина используют прежний `YANDEX_S3_BUCKET`.

До включения обмена файлами оператору нужно подготовить закрытый бакет,
проверить отсутствие анонимного чтения объектов и публичного списка, ACL,
политику бакета и права сервисного аккаунта на запись/чтение нужных объектов.
Скрытого списка недостаточно, если сами объекты доступны анонимно.
Настройки публичного доступа и ACL — отдельные механизмы:
[публичный доступ](https://yandex.cloud/ru/docs/storage/operations/buckets/bucket-availability),
[ACL бакета](https://yandex.cloud/ru/docs/storage/operations/buckets/edit-acl),
[обзор управления доступом](https://yandex.cloud/ru/docs/storage/security/overview).
Бакет, его ACL и политики в этой сессии не создавались и не изменялись.

Клиент передаёт байты серверу с UUID попытки и именем файла; PUT в бакет
не выдаётся клиенту. Поток ограничен 10 МБ, включая запрос без Content-Length.
Фактические байты хешируются SHA-256 и сохраняются по уникальному ключу
`jobs/{jobId}/attachments/{uploadId}/{sha256}/{serverUuid}/{fileName}`.
Метаданные добавляются под блокировкой заказа только после успешной записи.
Повтор того же UUID проверяет владельца, имя и содержимое. Параллельные копии
имеют разные ключи, поэтому удаление подтверждённо неиспользуемой копии не
затрагивает файл другого запроса.

Доступ к метаданным и подписанной ссылке проверяется для двух сторон выбранного
заказа или персонала. При скрытии заказа выдача участникам приостанавливается,
персонал сохраняет возможность проверки. Ссылка живёт 120 секунд, ответ не
кешируется; уже выданная ссылка действует до истечения срока. Файл отдаётся
с `Content-Disposition: attachment` и `application/octet-stream`.
Ключи хранилища не включаются в публичные API или props рабочих компонентов.

Файлы не исполняются и не распаковываются сервером. Автоматическая антивирусная
проверка этих вложений не добавлена; интерфейс предлагает проверять полученный
код перед запуском. Лимит — 50 подтверждённых файлов на заказ. Сдача результата
может ссылаться только на собственные подтверждённые файлы исполнителя.

При неизвестном результате коммита объект сохраняется. Общая сборка потерянных
приватных артефактов и политика хранения/удаления истории ещё не реализованы.
Не применять к `jobs/` очистку временных файлов товаров или удаление по возрасту:
эти объекты могут быть единственными экземплярами результата работы.
Проверка против настоящего S3 и проверка отказа анонимному GET остаются до выпуска.
