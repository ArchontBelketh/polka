# Пакет C1: характеристики товаров и фильтры магазина

Дата: 10 ноября 2026 года. Локальная реализация первой части пакета C из
[плана](CYBERPOLKA_V1_1_IMPLEMENTATION.md). Проверки кода и интерфейса пройдены;
это не завершение проверки полного цикла продажи.

## Каталог

У страницы `/catalog` и `GET /api/products` единый разбор параметров и построение
условий поиска: назначение (старая категория), поиск по названию/описанию, язык,
платформа, совместимость, лицензия, цена и сортировка.

- Цена переводится из рублей в копейки без умножения дробного числа. Поддерживаются
  точка и запятая; `NaN`, отрицательные суммы, лишние знаки и обратный диапазон отклоняются.
- Некорректные категории, языки, платформы, страницы и повторяющиеся фильтры
  не попадают в запрос БД. API возвращает 400, страница показывает понятное сообщение.
- Пагинация сохраняет фильтры. Применение формы и смена категории возвращают на
  первую страницу; сброс и кнопка «Назад» браузера синхронизируют поля с адресом.
- Размер страницы API — от 1 до 50, номер — от 1 до 10000. Внутренних потребителей,
  которым требовался бы прежний молчаливый пересчёт неправильных параметров, не найдено.
- Статус для гостя и обычного пользователя всегда `APPROVED`. Существующая возможность
  персонала фильтровать другие статусы сохранена, значения проверяются.
- Поиск по новым характеристикам отбирает только товары с такими сведениями.
  Старые товары без характеристик остаются в общем каталоге; язык/платформа им
  автоматически не назначаются из категории или свободного технологического стека.
- Коммерческая лицензия включает старое значение `team`. Другие старые значения
  лицензии не переписываются. Их текст больше не подменяется личной лицензией.
- Фасеты закрыты от индексации и имеют canonical на общий каталог/валидную категорию.
  Ошибки БД отличаются от пустого результата: страница показывает недоступность,
  API возвращает 503 вместо успешного ответа с нулём товаров.

Сортировки сохранены; к ним добавлен стабильный порядок по ID. Новые платные позиции
или изменения ранжирования Fair Exposure в этот пакет не входят.

## Характеристики и условия покупки

`ProductSpecification` — отдельная необязательная запись по `Product.id`:

| Поле | Правило |
| --- | --- |
| Языки | До 5 значений из справочника; фреймворки остаются в существующем стеке |
| Платформы | Windows, Linux, macOS, браузер, Telegram, 1С, Excel |
| Совместимость | Версии и среды, которые проверил автор |
| Результат покупки | Решаемая задача и состав поставки |
| Поддержка | Условия, объём и ограничения автора |
| Обновления | Условия предоставления обновлений |

Текстовые поля ограничены 2000 символами. На публичной карточке сведения обозначены
как данные автора; отсутствующие условия показываются как неуказанные. Новых
обещаний бесплатной поддержки, сроков ответа или обновлений по умолчанию нет.
Существующие требования, описание, примеры, инструкция и лицензия сохранены.
Доступ к инструкции после покупки остаётся прежним.

Один компонент полей используется при загрузке товара, в редакторе персонала
и в кабинете автора. Автор может менять характеристики только своего черновика,
отклонённой карточки или карточки с неудачной проверкой. Для опубликованного
и проверяемого товара правки проходят через персонал. Состояние публикации
повторно проверяется в транзакции вместе с записью характеристик.

Персонал сохраняет карточку, характеристики и запись аудита в одной транзакции.
Название можно исправить без изменения slug и уже опубликованной ссылки.
Товары, покупки, суммы, права доступа и существующие лицензии миграция не переписывает.

## Попутные исправления пути публикации и карточки

- Отказ подготовки загрузки, отсутствие URL или неуспешный PUT файла прерывают
  отправку на модерацию. Пользователь видит ошибку; созданный черновик остаётся в кабинете.
- Публичная карточка не использует приватный email как запасное имя автора.
- JSON-LD экранирует `<`, чтобы текст товара не закрывал тег `script`.
- ОС в метаданных берётся из явно объявленных платформ; неизвестным товарам
  больше не приписывается Web.
- Новые AI-аудиты с карточки не продвигаются. Результаты ранее заказанных отчётов
  и доступ к истории сохранены; старые обработчики заказов не удалены.
- Текст загрузки описывает базовую проверку и ручную модерацию без гарантии
  полной безопасности кода или неподтверждённого срока публикации.

## Схема и YDB

PostgreSQL: добавлена `20261110000300_product_specification`. SQL сопоставлен
с локальным `prisma migrate diff` между схемами; исполнения на настоящей базе не было.

YDB: подготовлена отдельная `003_product_specification`. Снимки и хеши `001_baseline`
и `002_developer_profile` сохранены. Метаданные кода содержат 35 моделей; облачная
база по последней проверке содержит исходные 33 бизнес-таблицы. Новые миграции
B2/C1 к ней в этом пакете не применялись. Readiness текущего кода требует все три шага.

В нативный адаптер добавлено условие `has` для строкового списка: фиксированный
JsonPath и отдельный типизированный параметр, без вставки значения в SQL. Основание:
[JSON-функции YDB](https://ydb.tech/docs/en/yql/reference/builtins/json) и
[передача параметров через PASSING](https://ydb.tech/docs/en/recipes/json-search/json-index-parameters).
Реальное выполнение этого условия и производительность при выбранном лимите RU
ещё требуют проверки после устранения таймаута SQL; JSON-индексы не добавлялись.

Перед запуском кода с данными необходимо применить добавочные миграции нужного
провайдера. Переключения приложения с PostgreSQL на YDB и развёртывания на сервере не было.

## Проверки

- Prisma validate/generate, TypeScript и production-сборка проходят.
- `ydb:schema:check` проверяет 35 моделей и три неизменяемых снимка без сети.
- 84 регрессионных теста проходят. Новые проверки покрывают фильтры и API,
  копейки/диапазоны, старые лицензии, права/состояния товара, связывание параметров
  YDB, создание характеристик, сохранение адреса, состав транзакции персонала,
  ошибки загрузки, приватный email и экранирование JSON-LD. БД и внешняя сеть
  в этих тестах изолированы; реальные транзакции/чтение YDB ими не подтверждаются.
- 11 браузерных сценариев на production-сборке проходят: 6 новых для каталога
  и гостевых запретов, 4 для публичной главной/навигации и 1 для профиля.
  На этом компьютере каталог показывает сообщение недоступности БД, поэтому
  эти сценарии проверяют формы, URL, навигацию, доступ и адаптивность, а не
  правильность выдачи настоящих товаров из базы.
- Компонент редактора отдельно проверен с подставленными ответами API/навигацией:
  лимит языков, конфликт с модерацией, ожидание, успех и сохранение полей при
  обрыве сети. Нет ошибок JavaScript и переполнения на 320, 375, 768 и 1440 px.
  Снимки: `test-screenshots/package-c1/`; снимки редактора показывают изолированные
  компоненты и не являются подтверждением авторизации или сохранения в БД.
- В `ydb:test` добавлен сценарий характеристик и фильтров на синтетическом товаре,
  включая отсутствие/появление совпадения и обратную связь с товаром. Он пока не запускался.

## Что остаётся в пакете C

После восстановления YDB: применить миграции в тестовом окружении, проверить
чтение/запись характеристик, реальные результаты комбинаций фильтров, старые товары,
модерацию, сохранение доступа к покупкам и удаление характеристик вместе с черновиком.

Полный контрольный путь C2: создание/загрузка → проверка → ручная публикация →
оплата → подтверждение → скачивание нужной версии → отзыв → возврат/выплата
по выбранному финансовому сценарию. Проверка настоящего S3 и платёжного провайдера
и перенос данных остаются отдельной работой. Возобновление прерванной загрузки,
защита мастера от повторного создания черновика и очистка временных объектов
теперь подготовлены в [пакете C2](PACKAGE_C_PUBLICATION.md); проверка с настоящими
БД и хранилищем ещё предстоит.
Пакет C не помечается завершённым до контрольной покупки.
