# Пакет B2: общий кабинет и профиль разработчика

Дата: 10 ноября 2026 года. Изменения подготовлены локально по пакету B
[плана](CYBERPOLKA_V1_1_IMPLEMENTATION.md). Код собирается и проходит проверки ниже.
Применение новых миграций к настоящей базе, авторизованные сценарии с БД и перенос
на сервер в этом пакете не выполнялись.

## Поведение аккаунта

- `/dashboard` доступен всем активным аккаунтам, включая покупателя. Покупки,
  избранное и обращения считаются только для текущего пользователя.
- В этом же кабинете можно перейти к готовому коду и существующей форме разработки.
  Пользователь с правами разработчика видит свои товары, продажи, подтверждения,
  сообщения и реквизиты. Инструменты персонала доступны отдельной ссылкой.
- Покупатель бесплатно включает режим разработчика без нового аккаунта. Смена роли,
  создание базового плана и профиля выполняются в одной транзакции. Существующие
  разработчики не теряют тариф или историю; системные роли не понижаются.
- `/dashboard/profile` — редактор профиля. Старые разработчики без новой записи
  получают пустые поля с сохранением имени, описания и товаров; запись создаётся
  при сохранении. Доступность по умолчанию — «Сейчас не беру заказы».

## Поля и публичность

Новая таблица `DeveloperProfile` связана с `User` по неизменному `userId`:

| Поле | Ограничения |
| --- | --- |
| Краткая специализация | До 120 символов |
| Направления | 1С, боты, интеграции, скрипты/автоматизация, веб-разработка |
| Навыки | До 20, каждый до 40 символов; повторы удаляются |
| Доступность | Открыт к предложениям / ограниченная / не беру заказы |
| Портфолио | До 6 проектов: название, описание вклада, необязательная HTTPS-ссылка |

Направления вынесены в общий справочник кода для будущих заказов. Старые категории
магазина сохранены; полная система связей категорий с биржей ещё не реализована.

Сохранённые сведения профиля публичны. Имя и «О себе» редактируются в общих
настройках. Публичная проекция не запрашивает email, телефон, Telegram, реквизиты,
баланс, пароль или системные полномочия. Товары запрашиваются отдельно без контактов автора.
Заблокированные аккаунты и аккаунты без прав разработчика скрыты и на странице,
и в метаданных. Метаданные и страница используют одинаковую проверку видимости.

Портфолио обозначено как добавленное автором; оно не выдаётся за подтверждённые
сделки. Статистика и рейтинг магазина относятся только к товарам. Отзывы по услугам
и история биржевых заказов не подменяются статистикой продаж.

## Доступ и формы

Общие `getCurrentUser`, `canManageCode`, `isStaff` применены к кабинету, настройкам,
редактору и API профиля, включению режима разработчика, странице загрузки,
страницам товаров и реквизитов. `auth()` продолжает проверять отзыв JWT;
проверка текущего пользователя дополнительно читает актуальные роль и блокировку.
Это начало объединения проверок, не полная переделка всех старых API.

API принимает владельца только из сессии, отклоняет лишние поля и небезопасные ссылки.
Сохранение показывает ожидание и ошибки; при сбое сети введённые значения остаются
в форме. Исправлен существующий отказ сохранения при очистке имени (`name: null`).

## Миграции

- PostgreSQL: добавлена `20261110000200_developer_profile`. Она создаёт таблицу
  и enum, не меняет существующие аккаунты, покупки, суммы или идентификаторы.
- YDB: исходный применённый `001_baseline` из 33 таблиц сохранён неизменным снимком
  с прежним хешем. Отдельная `002_developer_profile` создаёт только новую таблицу.
  Текущие метаданные кода описывают 34 модели.
- Мигратор сначала проверяет журнал и существующую схему, затем пишет `APPLYING`,
  создаёт недостающие таблицы этого шага и отмечает `APPLIED`. Прерванный шаг
  можно продолжить. Изменённый хеш, отсутствие уже применённой таблицы,
  нарушение порядка или новая таблица без записи журнала приводят к отказу.
- Readiness YDB требует обе применённые миграции. `ydb:schema:check` проверяет
  метаданные и соответствие неизменяемым снимкам без подключения к облаку.

Перед запуском этого кода в окружении с БД необходимо применить соответствующие
добавочные миграции. В облачной YDB сейчас подтверждён только старый baseline;
новая таблица в рамках B2 там не создавалась. Настройка провайдера остаётся прежней.

## Проверки

- `prisma validate`, генерация клиента и `ydb:schema:check` проходят.
- TypeScript и production-сборка проходят.
- 62 регрессионных теста: в том числе актуальные права, приватность публичных
  данных/метаданных, защита от подмены владельца, ограничения портфолио,
  атомарность включения режима, общий кабинет покупателя и совместимость миграций.
  БД/сеть в этих тестах изолированы; это не подтверждение работы живой YDB.
- 5 браузерных тестов на production-сборке: публичная главная и навигация,
  мобильное меню, гостевой запрет редактора и API.
- Отдельно проверены реальные компоненты форм в изолированном браузерном стенде
  с подменой ответов API и навигации: добавление/удаление проектов, лимит 6,
  ошибки сервера и сети, блокировка при сохранении, успех, очистка имени,
  переход к редактору после включения режима. Переполнения нет на 320, 375, 768,
  1440 px, ошибок JavaScript нет. Снимки находятся в `test-screenshots/package-b2/`;
  они показывают компоненты, не авторизованный сайт с реальными данными.
- Подготовлены 2 браузерных сценария с настоящей БД и проверка нового профиля
  в `ydb:test`; они в этом пакете не запускались.
